# 栖桌 · DeskNest

属于你的 macOS 桌面分区与菜单栏整理工具。基于 SwiftUI 与 AppKit，支持 macOS 14 及以上，Apple 芯片和 Intel Mac。

## 下载与更新

- **普通用户：[下载发布版](https://github.com/felixhui6791-art/DeskNest/releases/latest)**，选择 `DeskNest-版本号-universal.zip`。
- **测试使用：[查看测试版](https://github.com/felixhui6791-art/DeskNest/releases)**，选择带 `Pre-release` 标记和 `beta` 字样的版本。

解压后把应用拖到“应用程序”文件夹，再打开。当前版本使用临时签名，尚未进行 Developer ID 签名及 Apple 公证；首次打开如果被拦截，可在“系统设置 → 隐私与安全性”中选择“仍要打开”。不要关闭系统安全保护。

控制台左下角和应用菜单均有“检查更新”；“偏好设置 → 软件更新”可开关自动提醒。默认每天检查一次，发现新版后显示菜单栏更新标记和控制台提示，点击下载安装并重新打开。更新包和更新列表都经过 Sparkle EdDSA 签名验证。0.8.x 没有自动更新，需先手动安装 0.9.0 或更新版本。

| | 发布版 | 测试版 |
|---|---|---|
| 应用 | 栖桌 | 栖桌 测试版 |
| 更新来源 | 发布版 | 测试版 |
| 工作区目录 | `~/Library/Application Support/DeskNest` | `~/Library/Application Support/DeskNest-Beta` |

两个应用可以同时安装，文件引用和布局相互独立。菜单栏整理会操作同一条系统菜单栏，建议使用时只运行一个版本。测试版的更新不会推送给发布版用户。

## 本地开发运行

在项目目录打开终端，执行：

```sh
./scripts/run.sh
```

需要 Swift 6.0+ 开发工具链与 Python 3。脚本默认生成并打开独立的 `build/栖桌 测试版.app`。也可以单独执行 `./scripts/build-app.sh beta`，或使用 `./scripts/build-app.sh release` 构建发布版，然后双击生成的应用。脚本支持从任意目录调用，包含空格的路径请加引号。构建使用本机临时签名（ad-hoc）；这是用于自己电脑的构建，尚未进行 Developer ID 签名或 Apple 公证。

## 使用

- 为工作、生活或项目建立桌面分区卡片，调整名称与颜色。
- 将文件、文件夹或 `.app` 拖入分区。添加的是引用，原文件保留在原来的位置。
- 双击项目即可打开；通过项目的菜单在 Finder 中显示原文件。
- 拖动标题栏安排桌面布局，按需锁定位置或切换显示。鼠标移到分区四条边或四个角会显示对应的拉伸箭头，拖动即可调整大小；最小 160 × 140 点，宽高可独立变化。窄分区自动使用紧凑标题栏，文件仍可滚动查看。锁定位置后不能移动或拉伸。
- 拖动和调整大小时显示落点预览与对齐线，松手吸附到网格、屏幕边缘或相邻分区。按住 `Option` 临时自由摆放，并跳过避让。
- 自动识别原生桌面小组件的候选位置，在落位和「整理分区布局」时避让。扫描只读取窗口边界，不截图、不申请屏幕录制或辅助功能权限；基于系统宿主和窗口层级的识别可能遗漏，不能保证覆盖所有 macOS 版本。
- 在「偏好设置」中开关吸附与原生组件避让，也可重新扫描。先显示桌面，再从菜单栏选择「标记保留区域…」，拖出要留空的矩形，松手保存，按 `Esc` 取消；可在偏好设置中移除保留区域。
- 分区固定在桌面层，普通应用窗口会盖住它们，不会置顶遮挡工作内容。「锁定位置」仅防止误拖动。
- 从菜单栏选择「打开管理窗口」「新建文件分区」「隐藏桌面分区」或「整理分区布局」。关闭管理窗口后，桌面分区和菜单栏入口仍可使用；选择「打开管理窗口」即可恢复。选择「退出栖桌」可结束应用。

分区、文件引用和布局自动保存在 `~/Library/Application Support/DeskNest/workspace.json`。原文件被移动或改名后，引用可能失效；请将新位置的文件重新添加。移除分区中的引用不会删除原文件。第一版聚焦手动分组，后续可以加入按文件类型或目录规则自动整理。

## 标题栏显示

每个桌面分区和小组件可独立设置「显示标题栏」，入口在控制台的分区设置、侧栏右键菜单，以及桌面组件的右键菜单。关闭后隐藏名称、数量、添加按钮、菜单按钮和分隔线，顶部留白仍可拖动（锁定时不可拖动）；从右键菜单或控制台可恢复。内容、大小和配色不变，设置重启后保留。旧工作区默认显示标题栏。

## 小组件库

控制台左侧「小组件库」提供文件分区与系统监控，点击「添加到桌面」即可创建。系统监控每 3 秒读取本机内存使用量、比例及启动磁盘剩余空间，不需要新权限。可在控制台设置配色、显示状态和锁定，也可拖动桌面组件顶部或边缘调整布局。关闭管理窗口后仍显示，重启恢复。

内存显示以 Mach 虚拟内存统计估算应用驻留内存（扣除可清除页）、联动内存和压缩内存，排除文件缓存；它不是内存压力指标，可能与活动监视器的采样结果略有差异。硬盘读取启动数据卷的实际剩余容量，不计可清除空间，因此可能不同于 Finder 的可用容量。内存使用二进制容量单位，磁盘使用十进制容量单位。读取失败显示“暂不可用”。参考 [Apple 的内存指标说明](https://support.apple.com/en-euro/guide/activity-monitor/actmntr1004/mac)。

## 菜单栏整理

在管理窗口左侧选择「菜单栏整理」，或从栖桌菜单打开；快捷键为 `⌘ ,`。

玻璃配色提供雾白、淡灰、深空灰、石墨灰、雾蓝、鼠尾草、香槟、烟粉 8 种低饱和色，保留窗后模糊、渐变与高光边缘。深空灰和石墨灰使用深色材质、浅色文字；换色不会降低内容透明度。

- 「偏好设置 → 统一分区玻璃颜色」为桌面分区选择默认配色。
- 分区右上角菜单的「玻璃颜色」，或管理页的「分区设置 → 玻璃颜色」，可单独换色；「跟随统一配色」恢复使用默认配色。原有点缀色单独保留。
- 折叠面板的玻璃颜色统一在控制台「菜单栏整理」页面调整，立即生效并自动保存。

在「偏好设置」中，可以分别调整「分区背景透明度」与「折叠面板背景透明度」，范围 0%–85%。0% 为默认磨砂玻璃；数值越大，背景越通透，文字、图标和其他内容始终保持清晰。所有桌面分区共用分区背景设置，折叠面板独立调整，随时可以点「恢复默认」。设置实时生效、自动保存，重启后保留。折叠面板只保留图标与操作提示；右上角「调整」用于安排原菜单栏图标，外观设置集中在控制台。

1. 点击「调整图标位置」进入调整模式，原菜单栏持续展开，菜单栏箭头改为 ✓。
2. 按住 `⌘`，将不常用的菜单栏图标拖到竖线左侧。常用图标放在箭头右侧；竖线应保持在箭头左边。
3. 整理完成后点击菜单栏 ✓ 或「完成调整并收起」。之后点击向下箭头，内容显示在菜单栏下方的独立面板。图标直接显示在玻璃背景上，无黑色衬底或单独卡片底色，悬停可查看名称。点选项目可请求打开原图标菜单，结束菜单操作后恢复折叠；点外部或按 `Esc` 关闭面板。

休眠、显示器熄屏、用户会话切换和屏幕重排会保留本次运行中用户选择的折叠状态。唤醒后等待有效菜单栏布局和空闲间隔再恢复收起；系统重建分隔区域时也会自动校正。手动调整模式继续保持展开，直到主动完成。

默认启用且先显示原菜单栏，不会自行挑选或移动其他应用的图标。可选择不自动收起，或展开后 5、15、30 秒自动收起；鼠标停留在面板或菜单栏时暂缓。调整模式不启动自动收起计时，松开 Command 或点击其他应用后也保持展开，直到手动完成。在面板外按住 Command 点击菜单栏图标也会进入调整模式。关闭此功能或退出栖桌会恢复原菜单栏。分界线的位置由 macOS 保存。切换桌面或显示器后会恢复先前的折叠状态；打开原菜单产生的临时展开不受“不自动收起”设置影响，菜单仍打开时继续等待。

此功能参考 [iBar](https://apps.apple.com/cn/app/id6443843900) 的折叠区面板交互。面板从公开窗口元数据读取实际项目，空间不足时可滚动。原始图标预览需要「屏幕录制」权限，打开其他应用的图标菜单需要「辅助功能」权限；只在用户点击面板内的对应授权按钮时请求。未授权时显示可识别的名称和占位图标，并提示缺少的权限。

图标预览使用 ScreenCaptureKit，优先捕获目标状态栏小窗口；隐藏图标无法直接读取时，会短暂展开菜单栏，在 macOS 15.2 及以上读取经过位置校验的目标图标小区域，再恢复折叠。不捕获整屏、不采集音频；图标缓存只保留在内存中。已有真实图标立即显示，超过 15 秒后后台更新；更新失败继续保留上一次成功预览，不切回占位图标。应用退出、目标窗口消失或权限撤销时清理缓存；窗口身份或图标尺寸变化时重新读取。启动时会预先读取可见图标，点击“刷新”可主动重新读取。点选时会临时展开原菜单栏，再以实时坐标唯一匹配辅助功能项目并请求打开，不模拟鼠标点击、不移动第三方图标。若应用不支持或无法唯一识别，会显示原因并保留手动操作入口。部分系统项目不可移动；原菜单位置仍受刘海与屏幕宽度限制，macOS 版本或其他菜单栏管理器也可能影响兼容性。

本机临时签名会随重新构建变化。如果系统设置中已开启辅助功能、应用却仍提示缺少权限，请在最终构建完成后移除旧的栖桌授权条目，重新添加当前 `build/栖桌.app` 并开启；系统可能要求触控 ID 或密码确认。

## 开发与验证

```sh
swift build
swift test
```

测试后还需要在本机检查拖放、打开文件、桌面布局和退出重开后的恢复。更新运行中的应用前，先从菜单栏退出旧版本，再运行构建脚本。

手动验证时可用独立的数据目录启动，避免改变自己的分区：

```sh
"./build/栖桌.app/Contents/MacOS/DeskNest" --data-directory "/tmp/DeskNest Preview"
```
